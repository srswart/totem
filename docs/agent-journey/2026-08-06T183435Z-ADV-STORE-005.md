## 5. Corrections to the advance

Two, both recorded in the advance's `## Corrections to the Advance` section
rather than silently narrowing scope:

- The Outcome's "one command seeds a reproducible corpus into a fresh store"
  is delivered as a library call (`totem_store::corpus::seed` /
  `seeded_in_memory`), not a standalone CLI binary. The declared immediate
  consumers (ADV-CORE-005, ADV-GATEWAY-006, ADV-GATEWAY-008) are all Rust code
  that will call the library directly; a terminal-invokable wrapper is a small
  addition left for whichever of them (or a later workstation advance) first
  needs a human to run it by hand.
- "Golden query set with expected ranked results" is delivered as top-1 rank
  guarantee for one query and unordered membership for two others, not full
  multi-position precision@k scoring across the whole result set. That fuller
  scoring is explicitly ADV-GATEWAY-008's own job ("recall-quality scorer...
  reports ranking metrics") built on top of these fixtures — the intended
  division of work, not a gap found after the fact.

## 6. Invariants established only partially

- **Recall-quality signal is mechanical, not semantic.** Every fixture is
  embedded with the existing `DeterministicEmbedder` (trigram-hash, real
  cosine geometry, no network dependency — `embedding.rs`'s own doc comment is
  explicit about this). The golden queries prove the recall *plumbing* works
  end-to-end; they cannot and do not claim that a semantically meaningful
  query would rank the same way a real embedding model would. ADV-CORE-005
  inherits this caveat when it runs its quality evaluation against this
  corpus — recorded in both the advance body and here so it isn't
  rediscovered.
- **Reproducibility is shape-deterministic, not byte-deterministic.**
  `seeded_in_memory_is_reproducible_across_fresh_stores` asserts the
  `CorpusReport` (category counts) is identical across calls, which it is by
  construction — but `MemoryId` values (UUID v4) differ every run, by design
  (ids are minted, never caller-supplied, per `totem-core/src/ids.rs`). A
  consumer that pins on a specific `MemoryId` rather than on body/category/tag
  would not get a stable target.
