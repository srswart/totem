# Journey report — ADV-GATEWAY-014 (first advance of phase-011)

Workstation session, claim-first, on a phase branch forked from a master that
finally contains the deployed gateway (phase-010 merged as PR #62).

Recall responses no longer carry embedding vectors: **2,479 → 561 bytes for a
single record, 77% smaller**, measured rather than estimated because the
advance's own objective was cost and an unmeasured cost claim is a guess.

## Why this one was cheap and correct

The trim went in `ops::recall` — the single point both REST and MCP return
through — so the two surfaces cannot drift on what a client receives. That
placement was available only because ADV-GATEWAY-002 put the shared
operations there in the first place; a per-surface fix would have been the
same size today and a divergence risk forever.

The `public_api` risk (removing a field from a published response) was
discharged the way the advance demanded: by *checking* consumers, not
assuming. No reader of `content.embedding` exists outside `ops` — the console
renders body and scope, the CLI does not recall.

## Provenance of the finding

Reported by the first real agent use of the deployed gateway, in the same
session that found the `totem_save` schema bug. Two defects and one
efficiency finding, all from an hour of actual use, none reachable by 66
green test blocks. The dogfood trial has not formally started and has already
paid for itself twice.
