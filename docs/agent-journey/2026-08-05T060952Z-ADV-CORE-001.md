## 6. Invariants established only partially

Stated plainly, since the notes ask for this rather than a clean-sounding
summary:

- **Episodic append-only is guarded, not enforced.**
  `MemoryRecord::revise()` refuses append-only categories, but `content` is a
  public field on the struct, so a caller can still assign to it directly. The
  domain layer guards the intended mutation path; it does not make rewrites
  unrepresentable. Persistence-level enforcement is `ADV-STORE-001`'s job. This
  is stated in the crate docs and raised as CFU question 3.
- **Scope isolation is a type, not yet an enforced boundary.** `ScopeChain`
  makes the readable set explicit and impossible to widen accidentally, and its
  only constructor cannot produce another actor's private scope. But nothing
  reads or writes anything yet — the invariant that *every read path goes
  through store-enforced scope resolution* is `ADV-STORE-001`'s to establish.
  This advance provides the vocabulary that makes that enforcement checkable.
- **Provenance is required at construction, and that is the whole of it.**
  There is no access log yet (G3's second half), because there is nothing to
  log against. `ADV-GATEWAY-001` owns the access log.
- **Scope promotion policy is deliberately absent.** §2.2 assigns a per-category
  promotion policy (auto for Knowledge, human-gated for Instructions). Only the
  review-policy half of that is modelled here, via
  `CategoryLifecycle::review`; the propose/approve/demote engine belongs to
  `ADV-CORE-003` and was left out rather than half-built.

## 9. Review round (post-PR)

Copilot reviewed PR #1 and raised two inline comments on `scope.rs`. Both were
correct and both were fixed test-first, with the new tests confirmed failing
against the old implementation before the change:

1. **`Scope::from_str` mislabelled a bare known prefix.** `"actor"` (no colon)
   returned `ScopeParseError::UnknownPrefix("actor")`, contradicting that
   variant's own doc comment — `actor` *is* one of the four valid prefixes; the
   real fault was a missing identifier. `from_str` now splits prefix from
   identifier before matching, so `"actor"` and `"actor:"` behave identically.

   Worth recording honestly: **my own test pinned the wrong semantics.**
   `scope_rejects_malformed_wire_forms` asserted the misleading error, so the
   suite defended the defect rather than catching it. The lesson is that a test
   asserting an error *variant* deserves the same scrutiny as one asserting a
   value — writing it from the implementation's behaviour rather than from the
   intended contract is how this happened.

2. **`ScopeChain::resolve` let caller ordering decide precedence.** Team ids
   were kept in the caller's slice order, and chain position is precedence, so
   two callers with identical memberships could see different merged views —
   a `HashSet` iteration in `ADV-STORE-001` would have been enough to trigger
   it. Team ids are now sorted and deduplicated. The tier order
   (actor → project → team → platform) is unchanged, since §2.2 specifies it
   and it is not caller-supplied.

Both threads were replied to on the PR. The score moved 88 → 89 with the fixes.

A CLI detail worth knowing: a bare `arrive score` returns **0 (Green)** once the
branch is pushed, because with an upstream set it scores *unpushed* work only.
The figure that matters for review is `arrive score --base origin/master`, and
that is what the advance frontmatter records. A future run that reads a bare
`arrive score` after pushing will get a meaningless zero.

## Notes for future runs

  because the root `Cargo.toml` comment lists the future
