## Why this run exists

This is an out-of-band continuation of the same session that implemented
ADV-GATEWAY-009 (see `docs/agent-journey/2026-08-07T033441Z-ADV-GATEWAY-009.md`).
Its sub-PR (#43) merged into `advance/phase-008` before a Copilot review
comment landed on it, flagging a real privilege-escalation bug in the just-
merged code:

> `/enroll` authorizes solely against the client-supplied `snapshot.repo.git_repo`,
> but `sync()` keys the write by `snapshot.repo.id` and overwrites
> `repo.git_repo`. A bound token can therefore enroll *any* ARRIVE id by
> setting `git_repo` to its own binding, which will rebind (take over) an
> existing repo row and its landscape.
> — https://github.com/srswart/totem/pull/43#discussion_r3733269913

Confirmed correct: `enroll`'s original check only proved the *submitted*
snapshot named the caller's own repo — it never checked whether the ARRIVE
id being enrolled already belonged to a *different* repo. Since `sync()`
upserts unconditionally by ARRIVE id, this is a landscape hijack, not merely
an unauthorized read — strictly worse than the enumeration vector
ADV-GATEWAY-009 was written to close.

Since PR #43 was already merged and this session was told not to reopen it
or open a duplicate PR for the same change, this fix is a new, narrowly
scoped follow-up: a `fix/sub/phase-008/ADV-GATEWAY-009-enroll-rebind` branch
off the (now-merged) `advance/phase-008` tip, following the same
claim/test/fix/docs commit discipline as any other sub-PR.

## What changed

- `crates/totem-gateway/tests/auth.rs`: new
  `enrolling_a_snapshot_cannot_rebind_an_arrive_id_another_repo_already_owns`.
  Confirmed red first (compiles; the hijack succeeds with `200 OK`).
- `crates/totem-gateway/src/handlers.rs`: `enroll` now looks up the existing
  landscape row for the snapshot's ARRIVE id and, for a `Caller::Bound`
  credential, refuses to sync unless that row is unowned (first claim) or
  its stored `git_repo` already matches the caller's own binding. An
  existing row with no confirmed `git_repo` yet is refused the same way an
  unconfirmed landscape *read* already was (ADV-GATEWAY-009's own established
  pattern).
- `arrive/systems/058-totem-core/advances/ADV-GATEWAY-009.md`: Bug Fixes,
  Behavioral Change, Changes Made, and CFU updated to describe the finding
  and the fix, in the same advance record (not a new advance — this is a
  defect in work already attributed there).
