## What went right, and why

**The probe before the tests.** Five of this advance's decisions depended on
engine behaviour I could not read off the ADV-STORE-004 findings: whether an
HNSW index tolerates rows with no embedding, whether `array<float, N>` rejects a
wrong-dimension vector, whether `DEFINE EVENT ... THROW` actually aborts a write,
whether a *nested* predicate (`provenance.created_at`) still pushes into the
`KnnScan`, and whether `INFO FOR TABLE` exposes the index definition well enough
to assert on. I ran a throwaway probe inside the existing spike crate — which
already had SurrealDB compiled — got all five answers in one run, and deleted it.
Designing the tests against measured behaviour rather than guesses is why the
implementation went green on the first pass.

**The mutation checks were worth more than the green run.** The advance warns
that a test which passes against a deliberately broken implementation is worse
than no test, so I broke each invariant on purpose:

- Removing the SQL scope predicate (leaving the Rust merge filter) failed
  *exactly one* test — the EXPLAIN assertion. Every result-based isolation test
  still passed. That is the single most useful thing this run learned: with
  defence in depth, the plan assertion is not a nicety, it is the only witness
  that the filter is still in the query.
- Removing both filters failed 5 tests, which is what proves the result-based
  tests are not vacuous.
- Removing the append-only `EVENT`s failed only the two in-crate raw-statement
  tests; the integration-level test still passed on the Rust rule alone. That is
  why the in-crate tests exist.

**Refusing to leak existence.** `get` returns `Ok(None)` for another actor's
record rather than a denial, and `StoreError` has no "found but forbidden"
variant at all. Making it unrepresentable was cheaper than remembering not to
use it.

## What was hard, and what I chose

**Where to put the raw-statement tests.** The store's whole design is that there
is no public accessor for the connection — but the strongest tests (a raw
`UPDATE` on an episodic row; a `CREATE` with no provenance) need exactly that.
Integration tests in `tests/` are external crates and cannot reach it. I put
those five tests inside `src/schema.rs` and made `Store::connection()`
`#[cfg(test)]`-only. The public surface stays closed; the enforcement is still
tested. The cost is that a future test proving a *curator* cannot bypass scope
will have to live inside the crate too.

**Serde was the wrong tool for the row mapping.** `chrono`'s serde form of an
instant is an RFC 3339 string, and TD-004 records what a string-typed instant
does in SurrealQL: filters nothing, errors never. Deriving the mapping would have
reintroduced the exact bug the tech direction warns about. `src/row.rs` is
therefore ~420 lines of explicit field mapping with one conversion point for
datetimes — the largest single contributor to a Red score, and the right call.

**An invariant taken literally has a price.** The append-only `EVENT` refuses
*every* update to an episodic row, including a `use_count` increment. Solution
Intent §4 says every memory carries retrieval counters. Those two cannot both be
true. I kept the invariant verbatim ("never edited or deleted", per
`components/store.yaml`) and recorded the consequence: episodic metering has to
live in the access log, and ADV-CORE-002 / ADV-GATEWAY-004 inherit that. This
was not in the advance as authored; it is a real design constraint discovered by
implementing.

**No index on `scope`.** The obvious next optimisation would plausibly change
which operator the planner picks and silently retire the `KnnScan` assertion.
Deferred to ADV-GATEWAY-007 with a comment in `schema.rs` saying so, rather than
added now and discovered later by a test that stopped meaning anything.

defining what makes two records duplicates. That is a decision, not a detail. It

## Invariants established only partially

1. **Access log — not satisfied at all.** It is a `gateway` invariant
   (ADV-GATEWAY-001). A read through `totem-store` today leaves no audit trace.
2. **Episodic metering — impossible by construction**, as above.
3. **Scope isolation — enforced twice inside the store**, so a predicate
   regression alone changes no result. The EXPLAIN assertion is the guard.
4. **`ef` is unmeasured** — 40 by inheritance from the spike; ADV-STORE-005 owns
   measuring it (TD-003 is explicit that five rows cannot establish a floor).
5. **Server parity inherited, not re-executed** — this sandbox cannot run a
   `surreal` server; everything here ran on embedded `kv-mem`.
6. **Dedup is lexical, not semantic** — a paraphrase at two scopes still
   surfaces twice. Semantic consolidation is ADV-CURATOR-001.
