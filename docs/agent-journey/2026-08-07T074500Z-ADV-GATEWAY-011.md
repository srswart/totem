# Journey report — ADV-GATEWAY-011 (workstation probe, hypothesis refuted)

Phase-010 opened FRESH from a workstation session; sub-branch claimed first,
same discipline as cloud runs.

The probe did what probes are for: it refuted the plan's load-bearing
assumption in one afternoon, before a dollar of hosting. The real durable,
authenticated gateway was exposed over public HTTPS through a throwaway
cloudflared tunnel; MCP `initialize` succeeded with a bearer and was refused
without one — the transport and auth work over public TLS. But the claude.ai
connector dialog has **no header or bearer field at all**: OAuth Client
ID/Secret only, and Add attempted RFC 7591 Dynamic Client Registration,
failing with "Couldn't register with Totem's sign-in service."

Three findings recorded (MCP-012 host allowlist — fixed here with
TOTEM_MCP_ALLOWED_HOSTS; MCP-013 no static bearer in connectors; MCP-014
discovery documents hidden behind our own auth layer). H2 (egress) was never
reached and is recorded as untested rather than assumed.

Recommendation: an OAuth proxy in front of the gateway rather than OAuth
inside it — the dogfood plan, ADV-INFRA-002, and ADV-GATEWAY-012 are
reshaped accordingly.

Process note: the human ran the connector dialog (the API cannot create a
custom connector, and the permission classifier correctly blocked an
attempted workaround). The screenshots of the dialog and its failure were
the decisive evidence — a reminder that some findings live only in a UI.
