## What was built

  landscape read was the MCP tool `totem_landscape` (ADV-GATEWAY-002),
  unusable from a browser. Calls the same `totem_store::LandscapeRepository::
  view` the MCP tool does.
- `totem-console` (new crate): `view_model.rs` (parsing + grouping,
  target-agnostic), `app.rs` (Dioxus components, rendered/tested via
  `dioxus-ssr` — no browser needed), `api.rs`/`main.rs` (wasm32-only:
  `gloo-net` fetch calls + `RootApp`, a repo/actor/project form with a
  manual Refresh button).
- Workspace `uuid` dependency gained the `"js"` feature — required once
  totem-core (pulled in by totem-console) targets wasm32-unknown-unknown;
  inert everywhere else.

## What did not ship (correcting the advance's original scope)

1. **Live-query auto-update.** The advance's Behavioral Change claimed
   updates would "appear without a manual refresh via live-query updates."
   TD-009 (docs/tech-direction/surrealdb.md) is correctly the reason the
   console can't open its own SurrealDB connection — but the fix (a gateway-
   side live-query subscription relayed to the browser over SSE/WebSocket)
   is a distinct subsystem this advance did not build. Refresh is a button.
2. **Real browser verification.** No `dx`, no `trunk`, no browser in this
   sandbox. Verified instead with `cargo check --target wasm32-unknown-
   unknown` and `cargo clippy --target wasm32-unknown-unknown --all-targets
   -- -D warnings` (both clean) — proves the web build compiles and links,
   never that it renders correctly.
3. (New risk, not in the original advance) **No console authentication.**
   `RootApp`'s actor/project fields are free-text input — matches the open
   question in `docs/arrive-decomposition-gaps.md` ("Console human
   authentication ... likely reverse-proxy/SSO initially"), not safe beyond
   a single-team reverse-proxied deployment.

Both the advance file (`arrive/systems/058-totem-core/advances/
ADV-CONSOLE-001.md`) and `arrive/implementation-plan.yaml` (item status:
`in_progress`, not `done`) record this plainly.
