## What was built

- `crates/totem-store/src/landscape.rs` (new): `LandscapeRepository` with
  `sync` (idempotent, one-transaction write of a whole landscape snapshot —
  deterministic ids, `UPSERT` for entities, delete-and-relate for
  `owned_by`/`impacts` edges), `view` (the merged G2 read in one round trip
  using the TD-001-confirmed `->rel->table.field` graph-traversal syntax),
  and `sync_runs` (the append-only provenance trail). Migration 3 adds a
  `component_id` field (recovers a component's short artifact id from its
  system-namespaced record key `<system>__<component>`) and the `sync_run`
  table, guarded by the same `EVENT`-refuses-`UPDATE`/`DELETE` pattern
  `access_log` already uses.
- `crates/totem-arrive-sync/` (new crate): `read_repo_artifacts` parses
  `registry.yaml`, each named system's `system.yaml`, `components/*.yaml`,
  and advance frontmatter (closed by the first line that is exactly `---`,
  so a later Markdown horizontal rule in the body cannot truncate it early)
  into a `LandscapeSnapshot`. `sync_repo` parses and writes in one call.
  `serde_yaml` added as a new workspace dependency.
- `crates/totem-gateway/src/mcp.rs`: wired `totem_landscape` — ADV-GATEWAY-002's
  always-empty stub — to the real `LandscapeRepository::view`. Corrected the
  stub's `LandscapeParams.repo` doc comment: it names the ARRIVE registry id
  (`registry.yaml`'s `repo_id`), not the `owner/name` scope form
  `totem_recall`/`totem_save`'s `project` field uses — two different id
  spaces in this system. This was a scope addition beyond the advance's
  originally declared components (`arrive-sync`, `store`); corrected in the
  advance frontmatter to include `gateway`, with the reasoning recorded in
  the advance body.

`tests/dogfood.rs` (in `totem-arrive-sync`) is the advance's namesake proof:
it parses and syncs *this repo's own real* `/arrive/` tree — 1 system, 7
components, 24 advances at the time of this run — into a fresh in-memory
store and reads it back through `view()`, rather than exercising a synthetic
fixture.

## Corrections made to the advance itself

1. **`depends_on` dropped from scope.** The original objective listed
   `impacts`/`depends_on`/`owned_by` edges. The schema (from ADV-STORE-001)
   already declares `depends_on` as `component -> component`, but nothing in
   this repo's `/arrive/` artifacts declares an inter-component dependency —
   `implementation-plan.yaml`'s `dependencies` field is *advance -> advance*,
   a different relationship the schema has no edge for. Populating it would
   have meant inventing data. Left reserved in the schema for a future
   advance with a real source.
2. **Scope widened to include `gateway`.** ADV-GATEWAY-002's own stub doc
   comment named this advance as the trigger to remove it
   ("`totem-store` has no landscape repository yet... Not yet populated");
   leaving `totem_landscape` permanently empty after ingestion exists would
   have contradicted this advance's own Behavioral Change claim. `components`
   in frontmatter corrected from `["arrive-sync", "store"]` to
   `["arrive-sync", "store", "gateway"]`.
