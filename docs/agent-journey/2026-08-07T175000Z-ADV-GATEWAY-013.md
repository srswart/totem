# Journey report — ADV-GATEWAY-013 (cloud agents can reach Totem)

Workstation session, claim-first. Totem is now an OAuth 2.1 resource server:
RFC 9728 metadata outside the auth layer, `resource_metadata` in every 401,
and third-party token validation with mandatory audience binding. A claude.ai
connector authenticated through WorkOS AuthKit, recalled the project estate,
and wrote a memory whose provenance carries the *proven* subject identity.

## The finding: in-process tests cannot see a published contract

The connector attached, authenticated, and then could not write at all.
`SaveParams::author` was a `serde_json::Value`, so the published JSON Schema
declared no type; the client stringified the argument and the server rejected
it. **Sixty-six green test blocks, and no external client could call the
write path.**

Every MCP test constructs typed Rust arguments in-process. The schema — the
only thing an external client ever reads — was never exercised by anything.
This is the same shape as ADV-INFRA-002's finding that clients were built
against a gateway that never refuses: a contract nothing external consumes is
a contract nothing verifies. The new tests assert the *published* schema, and
one of them fails on any untyped parameter rather than on these two.

For the overnight-experiment log: the trial found two real defects within an
hour of first use, neither reachable by the test suite. This is the argument
for dogfooding, made by the dogfooding.

## A protocol bug the codebase's own docs prevented

Validation failures were first mapped to `AuthError::InvalidBinding` and
returned 403. That variant's doc comment says plainly it is an *issue-time*
error that never authenticates a request — and the MCP spec requires 401,
because a client told 403 concludes its permissions are wrong and never
refreshes the token. A prior author's documentation caught a subtle
interoperability bug that no test would have.

## Left open, named

A `totem_save` through the connector completed server-side while the client
waited indefinitely for a response. Unresolved and recorded: an agent that
never sees an acknowledgement retries, and duplicates are what a curator
later pays for. Also open: whether two cloud routines can hold distinct
identities, which ADV-INFRA-003's measurement depends on.
