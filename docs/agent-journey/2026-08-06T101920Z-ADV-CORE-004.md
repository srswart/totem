## 3. Advance implemented — complete

**ADV-CORE-004 — Investigation: value-attribution proxy experiment.**
Complete. Closes Solution Intent §9's "value attribution depth" open
question and the project brief's named key risk ("usage metering is easy,
value attribution is hard").

**Method chosen over the advance's literal instruction:** the advance's
Planned Work asked to "collect/construct sample sessions with known 'memory
actually mattered' labels." Rather than inventing synthetic sessions (which
would calibrate to whatever proxy I expected to win), I built a labeled
corpus from this repo's own real development history: 17 (finding →
consuming-advance) pairs drawn from every recorded tech-direction finding
(TD-001…TD-011, EMB-001…EMB-004, MCP-001…MCP-005) and the advances/code that
could have consumed each, cross-checked by directly reading
`crates/totem-store`, `crates/totem-gateway`, and `crates/totem-core`
against each finding's stated constraint — not by re-reading the tech
direction docs' own prose claims.

**Findings** (`docs/tech-direction/value-attribution.md`):
- **Outcome-linkage** (does the delivered code actually behave as the
  finding said it should) is the best predictor: precision 1.0, recall 0.92
  on this corpus. It misses exactly one row — MCP-001's secondary finding
  ("set `serverInfo.name` explicitly"), which was never applied in
  `ADV-GATEWAY-002`'s `mcp.rs` at all. That is a real retrieval-and-apply
  miss in this repo's own history, not a proxy-scoring artifact.
- **Citation** (the finding's own id appears in the consuming code/doc) is
  the pragmatic, cheap v1 stand-in: precision 0.80, recall 0.67. Both named
  failure modes from the advance's Outcome section showed up for real:
  *citation without use* (TD-008/TD-009, correctly cited as forward pointers
  with no live-query consumer built yet) and *use without citation*
  (TD-005, MCP-002, MCP-003 — the code is correct, nobody wrote the finding
  id down).
- **Retrieval/availability alone** has no discriminating power: precision
  0.71 at perfect recall — numeric confirmation of the brief's own risk
  statement.
- **Explicit feedback** (`totem_feedback`) has zero data points; the tool
  doesn't exist yet (`ADV-GATEWAY-004`, still `planned`).
- **Concrete gap surfaced, not just a research finding:**
  `provenance.derived_from` already exists in the schema
  (`crates/totem-core/src/provenance.rs`,
  `crates/totem-store/src/schema.rs:73`) but neither `SaveRequest`
  (`crates/totem-gateway/src/dto.rs`) nor `totem_save`'s MCP parameters
  (`crates/totem-gateway/src/mcp.rs`) expose a `derived_from` field to
  callers. The highest-precision signal cannot be captured from live traffic
  until a future advance (likely `ADV-CORE-002` itself, or `ADV-GATEWAY-004`)
  adds it.

**v1 recommendation for `ADV-CORE-002`:** lead `value_score` with the
citation signal; add `derived_from` graph linkage as a high-precision
booster once the gateway exposes it; do not weight raw `use_count` into
`value_score` directly (feed it into `currency`/freshness instead, matching
`Economics`'s existing field separation). Per-category: citation +
derived_from for Knowledge and Instructions (where this corpus's real data
sits); freshness-only for Context (its 12h default TTL leaves no time for
citation to accumulate); inapplicable by design for Episodic (append-only,
never value-ranked); Identity and Uncertainty deferred — no examples arose
naturally in this repo's own findings corpus.

## 6. What I could not satisfy

- **Not blinded.** One author (this run) both constructed the labeled corpus
  and judged the "mattered" ground truth against it — exactly the risk the
  advance's own Risk section names ("hand-labeled samples bias the proxy
  choice"). Building a real corpus from git history instead of inventing
  sessions narrows this risk (the labels are checkable against actual code,
  not against my own invented scenario) but does not eliminate it. Stated
  plainly in the findings doc §2 and §5, and the advance's Risk section is
  left in place rather than declared resolved.
- **No live telemetry.** Every proxy score describes what this repo's
  history *would* have measured, not what a running gateway has actually
  logged — no agent has yet run `totem_recall` against this repo's own
  findings during real development, and `totem_feedback` doesn't exist.
