# Journey report — ADV-INFRA-002 (Totem goes public)

Workstation session. Totem now runs at `https://totem-dev.fly.dev`: one
machine in `sin`, durable RocksDB on a Fly volume, bearer-authenticated,
fail-closed, with the memory estate and landscape migrated onto it.

## The finding that matters

**Deployment is a different kind of test, and it found three defects that no
amount of local testing could.** Every one depended on building or running
without a developer's convenient environment:

1. A missing `.dockerignore` meant `COPY . .` uploaded 49 GB of `target/` to
   the builder. The first deploy looked like an hour-long hang; it was an
   upload. No test can catch this because tests never build a container.
2. The workspace's declared MSRV (1.85) is fiction — the dependency graph
   needs 1.94. It builds locally only because workstations run newer
   toolchains. A container has no such luck.
3. **Every client was written against a gateway that never refuses.** The MCP
   connector, the console, and the CLI all send no credential. Invisible
   while the gateway was an unauthenticated loopback composition; obvious the
   moment it was deployed. Three advances (GATEWAY-013, GATEWAY-010,
   CLI-002) exist because this one was done.

Point 3 is the one worth carrying into the overnight-experiment log: agents
build correctly against the environment they can observe, and a gateway that
accepts everything teaches the wrong lesson. This is not an agent failure —
the same omission was made by the human-directed sessions too, right up until
Fly answered 401.

## Left unfinished, deliberately visible

Backup/restore is **not** verified. A snapshot exists and Fly's scheduled
snapshots are on, but no restore has been performed, so the backup is a hope.
The advance's task list keeps the unchecked box, the Evidence section names
it, and the runbook repeats it. The alternative — marking the advance
complete with a quietly downgraded claim — is exactly what the honesty rules
exist to prevent.

Also carried forward: no build-layer caching, so every deploy recompiles
SurrealDB and RocksDB (~10-15 min). A cargo-chef Dockerfile would fix it;
recorded as a known cost rather than rediscovered each time.
