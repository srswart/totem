  migration error is not a local failure.

  reach), and one because two fixture records shared a `created_at` and the
  scan's order was therefore the database's choice. The second produced a real
  fix in production code: `candidates` now orders by `created_at ASC, id ASC`,
  so the job is deterministic rather than incidentally stable.

## 6. Invariants established only partially

Listed in full in the advance under `## What This Advance Establishes Only
Partially`. The two a reviewer should notice first:

- **"Reversible from the console"** (`components/curator.yaml`) is reversible
  from the *API*. `CurationRepository::rollback`, `events` and `history` exist
  and are tested; no console surface renders them. That is ADV-CONSOLE-002's
  work and this advance deliberately does not pre-empt it.
- **The access log has no `curate` operation.** A curator scan is logged as
  `Recall` and a merge as `Save`, told apart only by endpoint
  (`/curator/dedupe/*`). An auditor cannot ask "show me everything the curator
  did" without matching on endpoint strings. Widening `AccessOperation` is a
  core change plus a migration, and ADV-CORE-006 is already the advance that
  does exactly that.

Also honest about: the 0.95 similarity threshold is a strict default, not a
measured value (nothing in this sandbox can measure one until ADV-STORE-005's
corpus exists); records without embeddings are skipped and counted rather than
compared by text; the scan is unbounded; and a store-refused merge ends the run
rather than skipping on.
