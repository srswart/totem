## 6. Invariants established only partially

Stated plainly, since `gateway.yaml` is stage `incubating` and the CLI
enforces none of this:

1. **`/enroll` and `GET /landscape/:repo` are authenticated but not
   repo-bound.** Any valid credential can sync or read any repo's landscape.
   The credential's `repo` is a memory-scope id (`owner/name`); a landscape is
   keyed by the ARRIVE registry id (`058-totem`). Different id spaces. Not a
   memory-isolation leak — the landscape is not scoped memory — but a real gap
   in "least-privilege".
2. **Refused requests append nothing to the access log.** No read or write
   goes unlogged, since a refused request never reaches the store. But
   *attempts* are not recorded either. Recording them needs a new
   `AccessOperation` variant in `totem-core`, outside this advance's declared
   component scope.
3. **Expiry is wall-clock with no skew tolerance.**
4. **`allowed_hosts` left at rmcp's loopback-only default** — a public
   deployment must widen it, which belongs with ADV-INFRA-001.
5. **Team-scoped credentials are enforced but not exercised end-to-end over
   HTTP** — unit coverage plus one integration refusal, no positive path.
6. **`router()` remains an unauthenticated composition.** Correct for
   in-process tests and a loopback desktop, but binding it to a public
   listener bypasses everything this advance adds. Prevented by naming and
   documentation, not by the type system.
7. **Credentials are process-local and non-persistent.** A restart forgets
   them; a multi-instance deployment does not share them. Durable credential
   storage belongs with the durable deployment (ADV-INFRA-001).

## 8. Notes for whoever analyses these reports later

**The mutation check was worth more than the red-green capture.** Step 5 warns
that "a test that passes against a deliberately broken implementation is worse
than no test". Rather than trusting that the tests were good because they were
written first, I stubbed both `Caller` authorization methods to return `Ok` and
re-ran: 8 of 17 integration tests failed, exactly the eight authorization
cases, with authentication and happy-path cases still passing. That is the
evidence that makes the suite credible, and it took two minutes. Recommend it
as standing practice for the remaining security-critical advances
(ADV-CORE-003, ADV-GATEWAY-006).

**A per-package test run hid a cross-crate break.** `cargo test -p
totem-gateway` was green while `crates/totem-cli/tests/enroll.rs` no longer
compiled — it built an `AppState` literal that the new `tokens` field broke.
Only `cargo clippy --workspace --all-targets` caught it. Worth running the
workspace-wide check before believing a per-package green.

**This sandbox's writable disk is smaller than a full workspace debug build.**
Two runs died with `No space left on device` mid-link (`target/` reached 29-31
GB against roughly 38 GB of allowance) after accumulating artifacts across
several separate incremental builds. `cargo clean` reclaimed 31.2 GB, and a
single clean sequence with `CARGO_INCREMENTAL=0` — fmt, then clippy, then test
— completed comfortably at about 24 GB. Recommend that sequence for future
runs rather than repeated incremental workspace builds; the failure looks like
a link error and reads like a code defect until you check `df`.
