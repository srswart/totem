Wrote `tests/embedding.rs` first, referencing `totem_store::{DeterministicEmbedder, Embedder, embed}` before any of those existed. The dependency graph for this workspace's cold `cargo test` run is dominated by SurrealDB's own compile time (documented in docs/tech-direction/surrealdb.md §3 as ~5m; this run took closer to 9), and — during that wait — the implementation files were written before cargo actually reached `totem-store` in the build queue. Then `git stash pop` restored the implementation and the identical test file went green (6/6). This is recorded honestly in the advance's Evidence section rather than glossing over the timing issue.
